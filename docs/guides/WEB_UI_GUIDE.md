## 任务管理

### 查看任务列表

任务列表显示所有已创建的同步任务，包含以下信息：

- **任务名称**: 任务的唯一标识
- **状态**: 
  - 🟦 待执行 (PENDING)
  - 🟩 执行中 (RUNNING)
  - 🟧 已暂停 (PAUSED)
  - 🟩 已完成 (COMPLETED)
  - 🟥 失败 (FAILED)
- **同步级别**: 库级别 或 表级别
- **源库/目标库**: 数据库信息
- **表数量**: 同步的表数量或"全库"
- **进度**: 执行进度百分比和已处理/总行数

### 任务操作按钮

每个任务提供以下操作：

- **详情**: 查看任务的详细信息
- **编辑**: 编辑任务配置（仅待执行或已暂停状态）
- **启动**: 启动任务（仅待执行或已暂停状态）
- **暂停**: 暂停正在执行的任务
- **删除**: 删除任务（仅非执行中状态）

### 任务详情抽屉

点击"详情"按钮可查看任务的完整信息：

**基本信息**:
- 任务ID、任务名称
- 同步级别、同步模式
- 源数据库、目标数据库
- 批量大小、工作线程数

**执行状态**:
- 当前状态、进度百分比
- 已处理行数、总行数
- 当前位置、运行时长
- 开始时间、结束时间

**错误信息**:
- 如果任务失败，显示详细的错误堆栈

**同步表列表**:
- 显示所有同步的表名

## 创建同步任务

### 打开创建页面

1. 点击右上角的"创建同步任务"按钮
2. 进入任务创建页面

### 填写基本信息

**任务名称**:
- 输入任务的描述性名称
- 例如："用户数据同步"、"订单表备份"

**同步级别**:
- **库级别同步（全库）**: 同步整个数据库
- **表级别同步（指定表）**: 同步指定的表

## 数据库和表选择

### 库级别同步

#### 1. 选择源数据库

**搜索数据库**:
```
┌─────────────────────────────────────┐
│ 🔍 搜索数据库名...         [✕]    │
└─────────────────────────────────────┘
```

- 在搜索框中输入关键词，实时过滤数据库列表
- 支持模糊匹配（不区分大小写）
- 点击 ✕ 按钮清除搜索，显示所有数据库

**选择数据库**:
```
┌─────────────────────────────────────┐
│ [全选]              已选 3 / 10      │
├─────────────────────────────────────┤
│ ☑ production                       │
│ ☐ test_db                          │
│ ☑ backup_db                        │
│ ☐ staging                          │
│ ☑ archive_db                       │
│ ...                                │

- 点击"全选"按钮选择/取消选择所有数据库
- 勾选需要同步的数据库

```

- 可以修改目标数据库名称

## 高级配置

### 同步模式

**全量同步 (FULL)**:
- 一次性迁移所有数据
- 适合首次同步或数据备份
- 速度快，但不支持实时更新

**增量同步 (INCREMENTAL)**:
- 基于 Binlog 实时同步
- 适合持续的数据复制
- 延迟 < 1秒

**全量+增量 (ALL)**:
- 先执行全量同步
- 然后自动启动增量同步
- 适合首次部署后需要持续同步的场景

### 批量大小 (Batch Size)

**作用**: 控制每次批量处理的行数

**建议值**:
- 小表 (< 100万行): 1000-2000
- 中表 (100万-1000万行): 2000-5000
- 大表 (> 1000万行): 5000-10000

**影响**:
- 批量大小越大，同步速度越快
- 但内存占用也会增加
- 需要根据服务器配置调整

### 表并发数 (Worker Count)

**作用**: 控制并发处理的表数量

**建议值**:
- 小规模同步: 2-4
- 中等规模同步: 4-8
- 大规模同步: 8-16

**注意**:
- 过高的并发数会增加数据库压力
- 建议根据数据库性能调整

### 索引优化

**启用索引优化**:
- 同步前删除非主键索引
- 同步完成后自动重建
- 可以显著提高写入速度

**适用场景**:
- 大表全量同步
- 索引较多的表
- 对同步速度要求高的场景

**注意事项**:
- 会短暂影响查询性能
- 需要足够的临时空间
- 建议在低峰期执行

### 并发一致性快照（enable_consistent_snapshot）

**作用**:
- 在全量阶段启用并发一致性快照读取。
- 前端在创建/编辑任务时通过“启用并发一致性快照（全量）”复选框控制。

**接口传参**:
- 勾选后，请求体会自动携带：`"enable_consistent_snapshot": true`
- 未勾选时为：`"enable_consistent_snapshot": false`
- 该参数属于任务请求体字段（`POST /api/tasks`、`PUT /api/tasks/:id`），不是 `application.toml` 全局配置。

**注意事项**:
- 开启后快照建立阶段会短暂使用 FTWRL（`FLUSH TABLES WITH READ LOCK`）。
- 建议在业务低峰执行大表全量同步，并确保源库账号具备相关权限。

## 自定义数据库配置

### 为什么要自定义数据库配置？

1. **跨服务器同步**: 源库和目标库在不同的服务器
2. **多源同步**: 每个任务使用不同的源数据库
3. **环境隔离**: 测试环境和生产环境使用不同的配置
4. **权限分离**: 每个任务使用独立的数据库账号

### 配置步骤

#### 1. 开启自定义源数据库

展开"自定义源数据库连接"面板，打开开关：

```
┌─────────────────────────────────────┐
│ ▼ 自定义源数据库连接         [ON]   │
├─────────────────────────────────────┤
│ 主机: [192.168.1.100]             │
│ 端口: [3306]                       │
│ 数据库: [production]                │
│ 用户名: [reader]                    │
│ 密码: [••••••••]                   │
│                                     │
│ [测试连接] [保存配置]               │
└─────────────────────────────────────┘
```

#### 2. 填写连接信息

- **主机**: 数据库服务器地址
- **端口**: MySQL 端口（默认 3306）
- **数据库**: 数据库名称
- **用户名**: 数据库用户名
- **密码**: 数据库密码

#### 3. 测试连接

点击"测试连接"按钮验证配置：
- ✅ 连接成功: 显示"源数据库连接成功"
- ❌ 连接失败: 显示具体错误信息

#### 4. 保存配置

点击"保存配置"按钮：
- 配置会保存到系统配置文件
- 所有任务都可以使用此配置
- 可以在系统配置页面修改

#### 5. 自定义目标数据库

同样方式配置自定义目标数据库：

```
┌─────────────────────────────────────┐
│ ▼ 自定义目标数据库连接        [ON]   │
├─────────────────────────────────────┤
│ 主机: [192.168.2.100]             │
│ 端口: [3306]                       │
│ 数据库: [production_replica]        │
│ 用户名: [writer]                    │
│ 密码: [••••••••]                   │
│                                     │
│ [测试连接] [保存配置]               │
└─────────────────────────────────────┘
```

### 配置示例

**示例1: 同机房同步**
```
源数据库:
  主机: 192.168.1.100
  数据库: production
  
目标数据库:
  主机: 192.168.1.101
  数据库: production_backup
```

**示例2: 跨机房同步**
```
源数据库:
  主机: 10.0.1.100
  数据库: production
  
目标数据库:
  主机: 10.0.2.100
  数据库: production_replica
```

**示例3: 公网同步**
```
源数据库:
  主机: source.example.com
  端口: 3306
  数据库: production
  
目标数据库:
  主机: target.example.com
  端口: 3306
  数据库: production_replica
```

## 系统配置

### HTTP 服务配置

```
监听地址: 0.0.0.0
监听端口: 8081
```

- **监听地址**: 
  - `0.0.0.0`: 监听所有网络接口
  - `127.0.0.1`: 仅本机访问
- **监听端口**: Web 服务的端口号

### 默认数据库配置

用于元数据浏览（获取数据库和表列表）：

```
默认源库地址: 192.168.1.100
默认目标库地址: 192.168.1.101
调试模式: OFF
```

**说明**:
- 这些配置是默认值，每个任务可以单独覆盖
- 调试模式开启后会输出详细的 SQL 语句

### Redis 状态持久化配置

```
主机: 127.0.0.1
端口: 6379
密码: (留空表示无密码)
数据库索引 (DB): 0
```

**重要性**:
- Redis 用于存储任务状态和 Binlog 位点
- 建议配置高可用的 Redis 集群
- 定期备份 Redis 数据

### 日志配置

```
日志级别: Info
☑ 开启控制台标准输出 (Stdout)
☑ 开启文件持久化输出 (File)
```

**日志级别**:
- Debug: 最详细的日志
- Info: 一般信息（推荐）
- Warn: 警告信息
- Error: 仅错误信息

**输出开关**:
- 控制台输出: 适合开发调试
- 文件输出: 适合生产环境

### 任务数据持久化配置

**持久化模式**:
```
○ 本地文件
● MySQL 数据库
```

**本地文件模式**:
```
数据目录: data
```
- 默认使用文件系统存储
- 适合单机部署
- 数据目录需要有写入权限

**MySQL 数据库模式**:
```
MySQL 主机: 127.0.0.1
端口: 3306
数据库: mysql_to_async
用户名: root
密码: ••••••••
```
- 使用 MySQL 存储任务数据
- 适合需要高可用的场景
- 需要先创建数据库和表结构

## 常见问题

### Q1: 搜索框找不到我想要的数据库/表？

**可能原因**:
- 搜索词拼写错误
- 数据库/表名不包含搜索词
- 大小写不匹配（但系统支持不区分大小写）

**解决方案**:
1. 使用更短的关键词
2. 尝试使用部分匹配（如 "prod" 而不是 "production"）
3. 清除搜索框，查看完整列表

### Q2: 全选按钮没有选中所有数据库/表？

**原因**: 全选按钮基于过滤后的列表操作

**解决方案**:
1. 清除搜索条件
2. 确认显示的列表是完整的
3. 再次点击全选

### Q3: 自定义数据库连接失败？

**可能原因**:
- 主机地址错误
- 端口号不正确
- 用户名或密码错误
- 数据库不存在
- 网络不通

**解决方案**:
1. 使用"测试连接"功能验证配置
2. 检查数据库服务是否运行
3. 确认数据库用户权限
4. 检查网络连接和防火墙设置

### Q4: 表列表为空？

**可能原因**:
- 未选择源数据库
- 数据库连接失败
- 数据库中没有表

**解决方案**:
1. 确保已选择源数据库
2. 点击"刷新"按钮重新加载
3. 检查数据库连接配置
4. 确认源数据库中是否有表

### Q5: 任务创建后无法启动？

**可能原因**:
- 未选择数据库或表
- 目标数据库配置错误
- 数据库权限不足

**解决方案**:
1. 检查任务配置是否完整
2. 验证目标数据库连接
3. 确认数据库用户有足够权限
4. 查看任务详情的错误信息

### Q6: 同步速度很慢？

**可能原因**:
- 批量大小设置过小
- 表并发数设置过低
- 网络延迟高
- 数据库性能瓶颈

**解决方案**:
1. 增大批量大小（建议 2000-5000）
2. 增加表并发数（建议 4-8）
3. 检查网络连接
4. 启用索引优化
5. 优化数据库性能

### Q7: 如何查看同步进度？

**方法**:
1. 在任务列表中查看进度条和百分比
2. 点击"详情"按钮查看详细信息
3. 查看"已处理行数 / 总行数"
4. 查看"当前位置"了解当前同步到哪个表

### Q8: 任务失败后如何重试？

**方法**:
1. 查看任务详情的错误信息
2. 解决问题（如修复连接、权限等）
3. 点击"编辑"按钮修改配置
4. 点击"启动"按钮重新执行

### Q9: 能否同时运行多个任务？

**答案**: 可以

**说明**:
- 系统支持多任务并发执行
- 每个任务独立运行
- 建议根据服务器性能控制并发任务数

### Q10: 如何删除任务？

**方法**:
1. 找到要删除的任务
2. 确保任务状态不是"执行中"
3. 点击"删除"按钮
4. 在确认对话框中点击"删除"

**注意**:
- 执行中的任务不能删除
- 删除任务会清空相关数据
- 建议先暂停再删除

## 最佳实践

### 1. 任务命名规范

使用描述性的任务名称：
- ✅ "生产用户表同步-20250325"
- ✅ "订单数据备份-每日"
- ❌ "task1"
- ❌ "同步任务"

### 2. 合理设置批量大小

根据表大小调整：
- 小表: 1000-2000
- 中表: 2000-5000
- 大表: 5000-10000

### 3. 利用搜索功能

**场景**: 需要同步所有用户和订单相关的表

**操作步骤**:
1. 搜索 "user"，全选匹配的表
2. 清除搜索
3. 搜索 "order"，全选匹配的表
4. 完成选择

### 4. 定期检查任务状态

建议：
- 每天查看任务列表
- 关注失败的任务
- 检查同步进度
- 查看错误日志

### 5. 使用自定义配置隔离环境

建议：
- 生产环境: 使用生产数据库配置
- 测试环境: 使用测试数据库配置
- 开发环境: 使用开发数据库配置

### 6. 利用索引优化

适合启用索引优化的场景：
- 大表全量同步
- 索引较多的表
- 对同步速度要求高

不建议启用索引优化的场景：
- 小表同步（影响不大）
- 增量同步（不需要）
- 低峰期执行（不急于完成）

### 7. 监控资源使用

关注以下指标：
- CPU 使用率
- 内存使用量
- 网络流量
- 数据库负载

### 8. 定期备份数据

建议：
- 定期备份目标数据库
- 保留 Binlog 文件
- 备份 Redis 数据
- 保存任务配置

## 界面性能优化建议

### 1. 减少列表项

如果数据库或表数量过多：
- 使用搜索功能过滤
- 分批创建任务
- 避免一次选择过多项

- 默认每 3 秒刷新一次任务列表

- 避免过于频繁的刷新

- 推荐使用 Chrome 或 Firefox
- 启用浏览器缓存
- 避免频繁清除缓存
